## Quick Deploy (5 Minutes)

### Step 1: Configure AWS

```bash
# Install AWS CLI if needed
brew install awscli  # macOS
# or download from: https://aws.amazon.com/cli/

# Configure credentials
aws configure
```

Enter your:
- AWS Access Key ID
- AWS Secret Access Key
- Default region (e.g., us-east-1)
- Output format (json)

### Step 2: Update Configuration

Edit `infra/config/app-config.ts`:

```typescript
export const devConfig: AppConfig = {
  alarmEmail: 'your-email@example.com',  // ← Change this
  instanceConfig: {
    cpu: '1 vCPU',
    memory: '2 GB',
  },
};
```

### Step 3: Bootstrap CDK (First Time Only)

```bash
cd infra
npm install
npx cdk bootstrap
```

### Step 4: Deploy

```bash
npm run deploy:dev
```

This will:
1. Build your Next.js app
2. Create Docker image
3. Push to AWS ECR
4. Deploy to AppRunner
5. Output your service URL

### Step 5: Access Your App

After deployment completes, you'll see:

```
Outputs:
AppStack-dev.ServiceUrl = https://xxxxxxxxxx.us-east-1.awsapprunner.com
```

Visit that URL to see your deployed app! 🎉

## Environment Variables

### Adding Variables

Edit `infra/config/app-config.ts`:

```typescript
environmentVariables: {
  DATABASE_URL: 'postgresql://user:pass@host:5432/db',
  API_KEY: 'your-api-key',
  NEXT_PUBLIC_API_URL: 'https://api.example.com',
}
```

Then redeploy:

```bash
cd infra
npm run deploy:dev
```

### Sensitive Data (Recommended)

For passwords and secrets, use AWS Secrets Manager:

1. Create secret in AWS Console
2. Grant AppRunner access (IAM role)
3. Reference in your app code

## Custom Domain Setup

### Step 1: Update Config

```typescript
// infra/config/app-config.ts
customDomain: 'admin.example.com'
```

### Step 2: Deploy

```bash
cd infra
npm run deploy:dev
```

### Step 3: Add DNS Records

1. Go to AWS Console → App Runner → Your Service → Custom domains
2. Copy the CNAME records shown
3. Add them to your domain's DNS settings (e.g., Route53, Cloudflare, GoDaddy)
4. Wait for validation (5 minutes to 48 hours)

## Monitoring & Alarms

### Email Notifications

You'll receive emails when:
- CPU usage > 80%
- Memory usage > 80%
- 4xx errors > 50 in 5 minutes

### View Logs

**AWS Console:**
CloudWatch → Log groups → `/aws/apprunner/nextjs-admin-dashboard`

**CLI:**
```bash
aws logs tail /aws/apprunner/nextjs-admin-dashboard --follow
```

## Scaling

### Adjust Instance Size

Edit `infra/config/app-config.ts`:

```typescript
instanceConfig: {
  cpu: '2 vCPU',    // Options: 0.25, 0.5, 1, 2, 4
  memory: '4 GB',   // Options: 0.5 to 12 GB
}
```

Redeploy to apply changes.

## Cost Breakdown

### Current Configuration (1 vCPU + 2 GB)
- **Base cost**: ~$3-5 USD/month
- **Additional**: Scales with traffic
- **Data transfer**: First 1 GB free, then $0.09/GB

### Cost Optimization Tips
1. Use smaller instances for dev: `0.5 vCPU + 1 GB`
2. Delete dev stacks when not in use
3. Monitor CloudWatch metrics to right-size

## CI/CD with GitHub Actions

### Setup

1. Create IAM role for GitHub Actions (OIDC)
2. Add secrets to GitHub repository:
   - `AWS_ROLE_ARN`
   - `AWS_REGION`

3. Push to branches:
   - `develop` → deploys to dev
   - `main` → deploys to prod

### Manual Trigger

GitHub → Actions → Deploy to AWS AppRunner → Run workflow

## Updating Your App

### Deploy New Version

```bash
cd infra
npm run deploy:dev
```

AppRunner performs **zero-downtime rolling deployment**:
1. Builds new container
2. Starts new instances
3. Health checks pass
4. Routes traffic to new version
5. Terminates old instances

### Quick Fixes

**Build Fails:**
```bash
cd frontend
npm run build
docker build -t test .
```

**Deployment Fails:**
```bash
aws sts get-caller-identity
cd infra
npx cdk deploy AppStack-dev -c environment=dev --verbose
```

**Service Not Starting:**
1. Check CloudWatch logs
2. Verify environment variables
3. Test health check endpoint locally
